## 方案概述（运行时重建，不改资源包）

### 总体策略

- 不改 `data/uiwindow.txt`、不新增/替换 prefab。
- **运行时重建**：
  - 以当前 prefab 作为“容器”，在 `OnShow()` 首次进入时创建 `NewUIRoot`。
  - 将旧布局根节点（或旧按钮/旧面板）整体 `SetActive(false)` 或从层级移除，使其不再显示。
  - 新 UI 通过 **复用现有控件作为模板**（克隆 `UIButton/UILabel/UISprite` 以继承 atlas/font/collider），再用 `UIGrid` 进行 3列布局，保证不重叠。

### 天梯页（整页重做）

文件：[CPvPRoomWindow.cs](file:///d:/Solarmax3/Assembly-CSharp/CPvPRoomWindow.cs)

1. 新增私有方法 `EnsureNewUI()`（在 `OnShow()` 最开始调用）
   - 若已存在 `NewUIRoot` 则直接返回，避免重复创建。
   - 从现有 prefab 内抓取模板：
     - 模式按钮模板：`buttonArray[0]`（或其他稳定按钮）
     - 文本模板：`playerName / playerMoney / playerScore / accumulation / seasonTip2`（用于复制字体与样式）
   - 创建 `NewUIRoot`，并创建：
     - 顶部信息区（名字/金币/分数/累计金币等）使用克隆后的 `UILabel`，位置统一规划。
     - 模式区 `UIGrid`（`maxPerLine = 3`，`arrangement = Horizontal`，设置 `cellWidth/cellHeight`，`pivot` 固定）放入 5 个按钮。
       - 5个按钮中，4个直接 **重用并移动原 `buttonArray[0..3]`**（从旧父节点 reparent 到 grid），避免破坏 `SetSublabelModel` 内对 `buttonArray` 的赋值逻辑。

   - 旧 UI 剔除方式：
     - 将除 `NewUIRoot` 以外的旧布局根节点（至少包含旧模式按钮区域、旧背景装饰、旧赛季奖励区等）统一 `SetActive(false)`。
     - 为避免把“模板”也一起隐藏，先完成 `NewUIRoot` 构建与 reparent，再关闭旧区域。
2. 清理 `SetSublabelModel` 中的旧重排/替换逻辑
   - 删除硬编码位置计算（`leftX/gap/topY...`）与动态克隆 `Btn_3v1_Dynamic`。
   - 删除“强行替换 3人混战为 3v1”的逻辑，改为：`3人混战`保留为原按钮；`3v1`只由新按钮承载。
   - 保留原 `nType`/赛季时间等逻辑对按钮 enable 与文案的控制；若 `SetSublabelModel` 会变更 `titleLable[]`，则确保新 UI 使用的是同一套 `UILabel`（通过 reparent/复用）或同步到新标签。
3. 统一文案来源
   - `3v1挑战` 文案使用硬编码或已有语言表 key（若无可靠 key，先硬编码，后续可再接语言表）。
