## 总结

当前运行时重建 UI 的实现会导致“图片丢失/布局混乱”，根因是：
- 将原按钮 `transform.parent` 改掉并强行 `localScale = Vector3.one`，破坏了原 prefab 的缩放/层级（NGUI 依赖 UIPanel/缩放链路）。
- 误把同一父节点下的其它子物体一起 `SetActive(false)`，导致背景/装饰/文本被隐藏，出现大片空白或仅剩部分卡片。

本次重做目标：
- **天梯页（CPvPRoomWindow）**：允许保留顶部信息栏与左侧赛季面板，只重做“模式按钮区”，并保证 **4人混战卡片明显更大**，其它四项（含 3v1）在右侧整齐排列，不丢图不重叠。
- **房间页（CreateRoomWindow）**：保持最初四卡横排的风格，在“2人切磋”右侧按相同间距插入 3v1（必要时整体平移保持居中），不重叠不丢图。
- **移除 AI/单机开局相关改动**：3v1 按钮仍走 `StartMatchReq`，由服务端处理匹配。

## 方案（实现层面）

### 1) 天梯页：只重做模式区，保留顶部/左侧（稳定且不丢图）

文件：[CPvPRoomWindow.cs](file:///d:/Solarmax3/Assembly-CSharp/CPvPRoomWindow.cs)

#### 1.1 重写 EnsureNewUI 的策略（不再移动原按钮）

- 取 `oldModeRoot = buttonArray[0].transform.parent` 作为旧模式区根节点。
- 新建 `NewModeRoot`（只用于模式区）作为 `oldModeRoot.parent` 的子节点：
  - `NewModeRoot.localPosition = oldModeRoot.localPosition`
  - `NewModeRoot.localScale = oldModeRoot.localScale`
  - `NewModeRoot.localRotation = oldModeRoot.localRotation`
- **不再对 `buttonArray[i]` 做 reparent**，改为全部 `Instantiate` 克隆：
  - `4人混战（大卡）`：从 `buttonArray[0]` 克隆，保留原 `localScale`（不要改成 1），并放在左列（保持“明显更大”）。
  - `2人切磋 / 队伍对战 / 3人混战`：分别从 `buttonArray[1..3]` 克隆，保留各自的 `localScale`。
  - `3v1`：从 `buttonArray[1]`（小卡模板）克隆一个，设置文案为 `3v1对战`。
- 右侧四张小卡使用 `UIGrid`（两列网格）保证不重叠：
  - 这里“3列布局”的含义：左列是大卡（1列），右侧小卡区域是 2 列网格（共 3 列）。
  - `smallGrid.maxPerLine = 2`，`arrangement = Horizontal`，`pivot = Center`，`keepWithinPanel = true`。
  - `cellWidth/cellHeight` 用小卡模板 bounds + padding 计算。
  - `smallGrid.localPosition.x` 通过大卡 bounds 计算偏移：`offsetX = bigBounds.extents.x + gap + (smallCellWidth * 0.5f)`。
- 事件绑定：
  - 大卡按钮绑定原逻辑 `OnFourClick()`。
  - 2人切磋绑定 `OnOneClick()`。
  - 3人混战绑定 `OnThreeClick()`。
  - 队伍对战绑定当前项目里“正常的队伍对战入口”（优先使用现有按钮的点击回调：克隆后沿用其原 onClick；如需统一，改为调用 `OnTwoClickEx()`）。
  - 3v1 绑定 `OnThreeVOneClick()`（保持走 `StartMatchReq`）。
- **剔除旧模式区**：
  - 仅 `oldModeRoot.SetActive(false)`，不再遍历并隐藏它的兄弟节点（避免隐藏到背景/左侧面板）。
  - 不再强制隐藏 `seasonReward/seasonTime`（用户要求保留顶部/左侧）。

#### 1.2 清理与一致性

- 彻底移除 `EnsureNewUI` 内对 `buttonArray[i].transform.parent` 与 `localScale = Vector3.one` 的操作。
- 3v1 文案统一：使用 `3v1对战`（与当前天梯按钮文案一致）。

### 2) 房间页：保持原四卡横排，在“2人切磋”右侧等距插入 3v1

文件：[CreateRoomWindow.cs](file:///d:/Solarmax3/Assembly-CSharp/CreateRoomWindow.cs)

#### 2.1 重写 EnsureNewModeUI 的策略（不再 reparent/不再全隐藏兄弟）

- 找到四张原卡片按钮（基于 label.Contains(语言文本) 继续使用当前识别方式）。
- 取 `oldRowRoot = uibutton6.transform.parent` 作为原模式行的根（包含四卡）。
- 新建 `NewRowRoot` 作为 `oldRowRoot.parent` 的子节点，继承 `localPosition/localScale/localRotation`。
- 克隆四张原卡片（不移动原对象），并按“原始四卡的 x 位置”放置：
  - 从原四卡读取 `localPosition` 的 `x/y`，把克隆卡放在相同位置，保证“保持最初格式”。
- 插入 3v1：
  - 找到“2人切磋”克隆卡的 `x`，计算卡间距 `dx`（使用相邻两卡 x 差的平均值，比如 `dx = x(队伍) - x(2人切磋)` 或 `x(2人切磋) - x(3人混战)`）。
  - 新增 `3v1` 卡从“2人切磋模板”克隆，设置 `x = x(2人切磋) + dx`，`y` 与原卡一致。
  - 为避免右侧越界：计算 5 张卡的整体 bounds，整体平移使其中心接近 0（`offset = -bounds.center.x`），保证仍居中且不重叠。
- 事件绑定：
  - 克隆卡沿用原 onClick（默认会保留），但为了稳妥，可以显式清空并绑定到对应 `OnOneClick/OnTwoClick/OnThreeClick/OnFourClick`。
  - 3v1 绑定到 `OnThreeVOneClick()`（走 `StartMatchReq(MT_Room, CT_3v1, ...)`）。
- **剔除旧模式行**：
  - 仅 `oldRowRoot.SetActive(false)`，不遍历隐藏其兄弟节点，避免把其它 UI 一并隐藏（例如房间号输入相关层级）。
